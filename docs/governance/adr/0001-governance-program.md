# ADR 0001：架构治理程序（Architecture Governance Program）

## 状态

已接受（2026-11-27）

## 背景

仓库经过多次快速迭代（Vanilla JS → Vue 迁移、数据流水线扩展、本地数据层升级），
积累了一批平行实现、死代码、文档与真实状态漂移、以及未机器化的架构约束。
本程序以「假设今天产品从零开始、但已知道全部真实需求」为视角，
通过安全、渐进、可验证的重构，让代码库向单一事实源、唯一实现、深模块、
低耦合、高可定位性收敛。

## 决策

1. **隔离 worktree 执行**：所有改动在独立 git worktree + 分支上进行，
   不触碰主工作树的未提交改动；每批有效改进独立 commit。
2. **批次闭环**：每批必须完成「扫描 → 分析调用方 → 选方案 → 迁移 → 删旧 →
   验证 → 防回归 → 记录」，禁止只建新抽象不迁移旧调用方。
3. **验证门禁**：涉及 `scripts/` / `config/` / 数据产出的批次，
   以 `fundctl.py check --offline`（+ 按需 `--agent-rules`）与相关 pytest 为通过标准；
   涉及前端源码的批次叠加 `npm run test:t0` 与受影响 Chromium 交互测试。
4. **Deletion Test**：每一层抽象都自问「删除它，复杂性消失还是扩散到调用方」；
   只有真正封装复杂性的抽象才保留。
5. **决策记录位置**：本程序的过程决策记录在 `docs/governance/adr/`（独立编号），
   产品/领域 ADR 继续放 `docs/decisions/`，避免与既有 0001–0004 编号冲突。
6. **待确认策略**：需要产品决策、重大架构变更或破坏性迁移的事项，
   记入 `docs/governance/TASK-POOL.md` 的「待确认」区，不阻塞其他独立批次。

## 后果

- 每个批次可独立评审与回滚。
- 进度、任务池、架构地图三份文件与代码同库演进，新 Agent 可无缝接手。
- 治理本身不再引入新的「治理框架代码」；只保留文档与既有门禁能力。
